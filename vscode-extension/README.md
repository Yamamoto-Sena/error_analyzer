# Debug Buddy — IDE拡張 (エディタプラグイン) PoC

`02_introduction_spec.md` / `01_requirements_definition.md` で定義されている Debug Buddy の
「修正案の提示」体験を、**VS Code拡張機能**として実装した場合の動作サンプルです。

## これは何か

開発者のPC内（VS Codeなどのエディタアプリの画面の中）で完結する挙動を再現します。

- コード上の該当箇所に **赤波線（Diagnostics）** を表示
- カーソルを合わせると **ホバー（吹き出し）** で「要約 / 根本原因 / 学習メモ」を教育的フォーマットで表示
- 電球アイコンの **Quick Fix** を押すと、その場でファイルを書き換えて安全なコードに修正

検知パターンは1つだけの最小プロトタイプです:
`foo.map(...)` のようにオプショナルチェーンなしで配列メソッドを呼んでいる箇所を検知し、
要件定義書のサンプルエラー「`TypeError`: 未定義オブジェクトへのプロパティアクセス (`reading 'map'`)」に対応します。
Gemini連携や `src/analyzer.ts`（本体アプリの解析エンジン）との統合は行っていません。

## 試し方（初心者向け・手順の詳細）

事前に必要なもの: **VS Code** と **Node.js**（インストール済みか不安な場合は、
ターミナルで `node -v` を実行して何かバージョンが表示されればOKです）。

### ステップ1: 依存パッケージのインストールとビルド

1. VS Codeで `C:\develop\vscode-extension` フォルダを開きます。
   - VS Codeのメニュー → `ファイル` → `フォルダーを開く...` → `vscode-extension` を選択。
2. メニューの `ターミナル` → `新しいターミナル` でターミナルパネルを開きます。
3. 開いたターミナルに次の2つのコマンドを順番に入力し、Enterで実行します。
   ```bash
   npm install
   npm run compile
   ```
   - `npm install`: 拡張機能を動かすのに必要な部品（TypeScriptなど）をダウンロードします。初回だけでOK、少し時間がかかります。
   - `npm run compile`: TypeScriptで書いたコード（`src/extension.ts`）を、実際に動くJavaScriptに変換します。エラーが出ずに終われば成功です。
   - コードを編集するたびに `npm run compile` をやり直す必要があります（毎回手で打つのが面倒なら `npm run watch` を使うと、保存する度に自動で再ビルドされます）。

### ステップ2: 拡張機能を試運転する（拡張機能開発ホストの起動）

1. VS Code画面の左端にある「実行とデバッグ」アイコン（再生ボタンに虫がついたようなアイコン）をクリック、または単純にキーボードの **`F5`** キーを押します。
2. 数秒待つと、**「拡張機能開発ホスト」というタイトルの、もう1つ別のVS Codeウィンドウ**が新しく開きます。
   - これは「作った拡張機能を実際に有効化した状態のテスト用VS Code」です。今後の操作はこの新しいウィンドウの中で行います（元のウィンドウはそのまま裏に置いておいてOK）。
   - もしウィンドウが開かない・エラーが出る場合は、ステップ1の `npm run compile` が正常に終わっているか確認してください。

### ステップ3: サンプルファイルで動作を確認する

「拡張機能開発ホスト」ウィンドウの中で操作します。

1. `ファイル` → `フォルダーを開く...` で、同じ `vscode-extension` フォルダ（またはその中の `sample` フォルダ）を開きます。
2. `sample/risky-example.ts` をクリックして開きます。
3. コード中の `items.map(` という部分の下に、**赤色の波線**が表示されているはずです。これがエラー（かもしれない箇所）の指摘です。
4. その赤波線の上に**マウスカーソルを乗せて数秒待つ**と、吹き出し（ツールチップ）が出て「要約 / 根本原因 / 学習メモ」という形式で説明が表示されます。
5. 赤波線が引かれている場所に**カーソル（テキスト入力位置）を置き**、次のどちらかを行います。
   - 行の左側に出る**電球マーク💡**をクリックする
   - キーボードで **`Ctrl` + `.`**（ピリオド）を押す（Macなら `Cmd` + `.`）
   - どちらでも「Quick Fix」の候補メニューが出ます。
6. 候補の中の `"?." を追加して安全にする → items?.map(...)` のような項目をクリック（またはEnter）します。
7. コードが自動的に `items.map(` → `items?.map(` に書き換わり、赤波線が消えます。
   - 気に入らなければ **`Ctrl` + `Z`**（元に戻す）でいつでも元通りにできます。

### ステップ4: 自分のコードでも試す

`sample/risky-example.ts` 以外の `.ts` / `.js` ファイルを開いて、
`someVariable.map(x => x)` のようなコードを書いてみると、同じように赤波線・ホバー・Quick Fixが動作します。

### 終了のしかた

「拡張機能開発ホスト」ウィンドウをただ閉じるだけで終了します。何かが自動的にインストールされたり
PC全体に影響が残ったりすることはありません。次にまた試したいときは、ステップ2から再開してください。

## いつでも戻せるようにする方針

このPoCは **`feature/ide-extension-poc` ブランチ上でのみ** 作業しています。
`main` ブランチには一切影響を与えていません。

- 採用しない場合: このブランチを削除するだけで元通りです。
  ```bash
  git checkout main
  git branch -D feature/ide-extension-poc
  ```
- 採用する場合: 通常通り `main` にマージ、または PR を作成してください。

## 既知の制約（PoCゆえの割り切り）

- 正規表現ベースの簡易検知のみ。実際のASTを解析していないため誤検知/見逃しがあり得ます。
- 検知パターンは `.map` `.filter` `.forEach` `.reduce` `.find` の5メソッドのみ。
- Debug Buddy本体（Tauriアプリ）の解析エンジンやGemini APIとは未連携。
- テストコードは未整備（動作確認は手動での `F5` 起動のみ）。
